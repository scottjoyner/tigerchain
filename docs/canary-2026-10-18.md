# TigerChain production-readiness canary — 2026-10-18

**Decision: PRODUCTION NO-GO.** Research-only validation on `x1-370`.
This is a repeatable source-and-test checkpoint, not an admission receipt or
authorization to publish `kipnerter.com` endpoints.

## Completed in this development slice

### Authentication and tenant isolation

- Real FastAPI `/auth/register` and `/auth/token` tested against isolated
  SQLite user records. The HTTP upload and query endpoints used actual
  `DocumentIngestionPipeline`, `TigerGraphClient`, `MinioObjectStore`
  (against a SeaweedFS S3-compatible test server), and
  `TigerGraphVectorRetriever`.
- The LLM answer generator and embedding functions were deterministic test
  doubles. No external model calls, personal files, or fleet graph data.
- Two synthetic users each uploaded and queried documents. The test confirmed
  owner-scoped graph retrieval, SQL document listing, private/sharing request
  denials, JWT denial, deactivation/revocation, and staging cleanup.
- An optional `TIGERCHAIN_CANARY_ACK=SYNTHETIC_ONLY` enables the **same**
  HTTP test fixture against real disposable TigerGraph and S3 endpoints via
  `TIGERCHAIN_CANARY_GRAPH_URL`, `TIGERCHAIN_CANARY_S3_URL`, and isolated
  credential environment variables. Private RFC1918 addresses and explicit
  acknowledgement are required. Ordinary CI uses memory-backed fakes.
- JWT `sub` and graph owner scopes are now random account
  `users.principal_id` values (128 bits), **not** recyclable SQL row IDs.
  The real graph canary verified that legacy numeric tokens are rejected,
  old numeric-owned graph rows remain invisible, and new UUID-owned records
  are returned only to the corresponding principal.
- Self-registration is disabled by default. It is also denied when an
  administrator numeric-ID allowlist is configured, even if the development
  registration switch is set. An operator-only interactive bootstrap script
  can seed normal user accounts without opening public registration.
- The legacy unauthenticated `worker/api.py` was deleted. Builder UI and API
  operations now require administrator identity.

### Request and privacy guardrails

- Input metadata attempting to impersonate `owner_id`, `user_id`,
  `doc_id`, `embedding_scope`, sharing scope, and system provenance is
  rejected. Uploads are capped at 8 files, 32 MiB each, 64 MiB per request,
  and 16 KiB JSON metadata. Staging directories are removed on errors.
- Until genuine shared-document ACLs are implemented, document sharing is
  restricted to `private`; the experimental private embedding path remains
  disabled by default. Do not enable it for sensitive data.

## Remaining blockers — do not merge or deploy

1. **Migration gate:** existing SQLite/Postgres user tables need a verified,
   versioned `principal_id` migration. Numeric graph owner keys and JWT
   subjects intentionally no longer work; there is no automatic legacy
   backfill. Keep legacy production databases untouched until there is an
   independently reviewed mapping, migration/rollback plan, and proof against
   stale-token and ID-reuse attacks.
2. **Object storage gate:** SeaweedFS proves only S3-API compatibility.
   The tested AIStor image required a license and denied operations without
   one. Choose a licensed/supported store, implement per-tenant bucket/prefix
   ACL enforcement and encryption, test restore and lifecycle, and pin images.
3. **Production API gate:** build and boot the **latest exact** code SHA with
   real model dependencies, verify deep readiness, cold restart, resource
   limits, timeouts, and database connection pooling. The CPU image built
   before several subsequent security commits; it is a packaging proof only.
4. **Query performance gate:** the GDS query performs an exhaustive scan,
   not ANN. Benchmark realistic corpus quality, latency, concurrency, and
   memory against the existing Neo4j retrieval path before integrating with
   AssistX, Hermes, Sophia or OpenCode.
5. **Integrity gate:** rate limiting, arXiv download bounds, partial-ingest
   rollback, durable idempotency, independent authorization review, key
   rotation/secret-history assessment, and cryptographic audit receipts
   remain open.
6. **Migration/ops gate:** review Docker volume backup semantics and schema
   changes with graph service lifecycle; demonstrate an independently
   restored backup and planned rollback instead of equating recreation with
   recovery.

No fleet-control authority or production request routing has been granted.
All written graph/object examples were synthetic and limited to disposable
Docker projects on a separate internal-only network.
