## Environmental blockers

- Original `tigergraph/tigergraph:latest` is Enterprise Edition: unable to start database without a license. Community Edition used instead.
- Original `quay.io/minio/minio:latest` returned 401 at registry; updated AIStor image started but **denied all S3 operations without a license**. Storage compatibility was proved only against a separate S3-compatible canary. Do not represent as a MinIO pass.
- GSQL vector top-K currently uses an **exhaustive scan** of the authenticated owner's public vectors. No ANN index, realistic query load, or production-size recall/latency benchmarking was performed.
- Production Docker image has not been built or booted with all dependencies; no TestFlight, router or fleet deployment was attempted.

## Release blockers / next gates

1. Full API registration and JWT two-user tenant isolation against live disposable graph/S3, including negative and revocation checks. Role gating and stored-document ACLs must be proven.
2. Graph schema versioned, idempotent migration plan; prior graph data and attributes must be handled. Avoid implicit startup migrations.
3. Decide, license, pin and exercise the production object-storage provider. Object-level tenant permissions, key custody, encryption and delete/lifecycle recovery are not proven.
4. Build and boot pinned API image. Probe deep readiness, startup failure, instance kill/restart, idempotency, upload length and arXiv download resource limits.
5. Add repeatable authenticated graph/vector performance benchmark versus existing Neo4j path, collect p95 under concurrency, memory/disk and relevance metrics.
6. Independently review GitHub code, secret history, legacy unauthenticated API removal, and rollback plan before even a read-only fleet canary.

**Never make this draft PR production-ready based solely on this evidence.**
